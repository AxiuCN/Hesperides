# 抓取协议

## 接口

```js
// 供调用方（Atlas-Plugin）使用；CLI 也走这两个
harvestChannels(channels, { dataDir, mode, concurrency, onChannel })
harvestChannel(channel, { dataDir, mode, concurrency, previous, fetchImpl, delay })
```

- `channels`：频道定义数组（来自 `sources/alioth/channels.mjs`，调用方自行筛选）
- `mode`：`incremental`（默认）/ `full`
- `previous`：上一轮的 manifest 片段，由 `harvestChannels` 从 `manifest.json` 取出并传入

**本模块不读环境变量、不读插件配置、不跑定时任务**——抓取时机与范围完全由调用方决定。

## 增量模型

| 频道类型 | 判据 | 行为 |
|---|---|---|
| 全部 | 索引 `If-Modified-Since` → 304 | 整频道跳过 |
| 全部 | 索引内容指纹与 `manifest.indexHash` 相同 | 整频道跳过（上游不给 304 时兜底） |
| `phased` | `phaseVersions[id] !== 当前 Ver` | 只抓变化的期 |
| `ids` / `single` | 索引变了 | 整批重抓（版本更新时条目普遍变化） |
| `static` / `text` | 每个文件的指纹 | 只重写变化的文件 |

稳态成本：索引未变时，一次更新只发 7 个请求（终局频道各 1 个）。

## 状态语义

| status | 含义 | 是否保留旧数据 |
|---|---|---|
| `ok` | 本轮成功（`failed>0` 为部分失败） | 是 |
| `skipped` | 内容未变 | 是 |
| `absent` | 上游 404（契约有、线上无） | 是 |
| `failed` | 索引失败或整批条目失败 | 是（manifest 不覆盖旧记录数） |
| `unverified` | 尚未验证 ID 来源 | 是 |

**任何状态都不删旧数据**；插件据此决定展示「数据截至」还是报错。

## 写盘与续跑

1. 每条记录 / 每个文件：同目录临时文件 + `rename`
2. **每个频道结束就写一次 `manifest.json`** → 进程被杀后重跑只补没抓的
3. 导出（`index.json` / `periods.json`）在所有频道结束后统一生成，也可单独 `--export` 重建

## 限速

- 索引请求：串行（每频道 1 次）
- 分片请求：并发 `concurrency`（默认 4），每次请求后 `100~220ms` 随机间隔
- 重试：最多 2 次，线性退避；超时 20s
- UA：`Hesperides/<ver> (+repo)`

## 期规范化

见 `src/sources/alioth/normalize.mjs`：

1. 期列表按 `Ver` 排序（同版本按 `begin`）
2. `begin` 早于前一期 → 尝试 +1/+2 年，取保持单调的最小修正
3. `end` 早于 `begin` → 同样加年
4. 被修正的期标 `timeCorrected: true` 并保留 `rawTime`

## 命令行

```bash
node src/cli.mjs --list-channels
node src/cli.mjs --channel alioth:gi:abyss
node src/cli.mjs --channels alioth:gi:abyss,alioth:hsr:as --mode full
node src/cli.mjs --all
node src/cli.mjs --export
node src/cli.mjs --verify
```

退出码：`0` 全部成功 / `1` 有失败或校验不过。`--json` 输出机器可读摘要。
