# 源适配：玉璃（alioth.wiki）

## 端点

| 用途 | 地址 |
|---|---|
| 数据 | `https://json.alioth.wiki/data/{game}/{lang}/{path}` |
| 文本 | `https://json.alioth.wiki/TextMap/{GI\|HSR}/{file}` |
| 图片 | `https://img.alioth.wiki/{gi\|sr}/{category}/{file}.png`（玉璃侧仍不抓；nanoka 页面的图片由 `src/images/` 负责） |

- `lang` 用 **`ch` / `en` / `jp` / `kr`**（不是 `zh`），当前只取 `ch`
- 根级文件（`gi/banner.json`、`gi/GrowCurves.json`、`hsr/banner.json`、`hsr/eg.json`、`hsr/hlg.json`、`hsr/hsrboss.json`）**不带语言目录**
- 契约清单来自上游仓库 `alioth-wiki-code` 的 `data-directories.json`（本仓库文档里抄录一份；上游改结构时据它对比）

## 频道类型

| kind | 含义 | 例子 |
|---|---|---|
| `single` | 单个 JSON 就是数据 | `gi:achievement`、`hsr:cw` |
| `phased` | 索引里 `Phases[]._id` → `{page}/{id}.json`，同时产出期索引 | `gi:abyss`、`hsr:as` |
| `ids` | 用选择器从索引取 id → `{page}/{id}.json` | `gi:monster`（`Templates` 字典键） |
| `static` | 固定文件列表 | `gi:tps`、`hsr:cw-categories` |
| `text` | TextMap 大文本 | `alioth:textmap:gi-readable` |

## ID 来源（2026-11 实测，非猜测）

| 频道 | ID 来源 |
|---|---|
| `gi:char` / `char-story` / `char-voice` | `char.json` 的 `Avatar[].ID` |
| `gi:char-gun` | `char.json` 的 `Gun[].ID` |
| `gi:char-flycloak` | `char.json` 的 `Flycloak[].ID` |
| `gi:weapon` | **`char.json` 的 `Weapon[].ID`**（没有独立的 weapon 索引） |
| `gi:relic` | **`char.json` 的 `Relic[].ID`** |
| `gi:monster` | `monster.json` 的 `Templates` 字典键 |
| `hsr:monster` | `monster.json` 的 `Templates[]._id`（数组） |
| `hsr:relic` | `char.json` 的 `Relic` 是"对象套数组"，取各数组的 `ID` |
| `hsr:cw-char` | `cw.json` 的 `Characters[]._id` |
| 终局 7 频道 | 索引 `Phases[]._id` |

## 已知上游缺陷（都被规范化处理或可容忍）

| 现象 | 例子 | 处理 |
|---|---|---|
| `Time` 年份写错 | 危战 6.4~6.7 写成 2025（应为 2026） | `normalize.mjs`：期序按 `Ver` 排，begin/end 做年份修正并标 `timeCorrected`，原值留 `rawTime` |
| `end` 早于 `begin` | 危战 6.4 `2026-03-04 ~ 2025-04-07` | 同上，end 加年 |
| 契约有、线上没有 | `hsr/hsrboss.json` 返回 404 | 频道状态 `absent`，不算失败、不删旧数据 |
| 数据超前 | 已入库 gi 7.3、hsr 4.7-4.8 | 「本期」必须按 `begin ≤ now ≤ end` 判，不能取 `Phases[0]` |

## 覆盖范围

- **只有原神与星铁**（`data/zzz/**` 全 404），绝区零仍需 nanoka.cc
- 终局 7 个玩法：gi `abyss` 60 期 / `theater` 30 期 / `stygian` 13 期；hsr `chaos` 43 / `fiction` 28 / `as` 22 / `arbitration` 11

## 图片规则（玉璃，2026-11 实测）

玉璃记录里的图片字段只有**资源名**（原神）或**带目录的相对路径**（星铁），不带完整 URL。
真实文件按下面的规则拼，规则实现在 `src/images/refs.mjs` 的 `SOURCE_IMAGE_RULES.alioth`：

```
https://img.alioth.wiki/<gamePath>/<目录>/<资源名>.png
```

| 要点 | 结论 |
|---|---|
| 域名 | `img.alioth.wiki`（另有 `transform.alioth.wiki/i/…?w=N&f=auto` 提供缩放，本引擎用原图） |
| 游戏路径段 | 原神 `gi`；**星铁是 `sr`，不是 `hsr`**；玉璃没有绝区零 |
| 扩展名 | `.png`（nanoka 那边是 `.webp`） |
| 星铁的目录 | 记录值自带（`mostericon/…`、`monsterfigure/…`），注意 `mostericon` 是上游的拼写，少一个 n |
| 原神的目录 | 记录值只有资源名，按前缀推：`UI_MonsterIcon_`/`UI_ItemIcon_` → `MonsterIcon/`，`UI_AvatarIcon_` → `AvatarIcon/`，`UI_Img_LeyLineChallenge_` → `LeyLineChallenge/` |

两处反直觉但已实测确认：`UI_ItemIcon_*` 也放在 `MonsterIcon/` 目录下；幽境危战的展示图单独占 `LeyLineChallenge/`（单张约 300 KB）。

**落盘归一**：URL 里的 `sr` 段在产物路径里统一写成 `hsr`（`images/hsr/mostericon/…`），否则同一游戏的图会被拆成两个目录。

## 合规

- 数据抓取自公开站点，仅供本地自用；**不随仓库分发**（`data/` 在 `.gitignore`）
- 抓取限速：并发默认 4，分片间隔 100~220ms 抖动，UA 标明 `Hesperides/<ver>`
- 引用仓库自身代码（Nuxt 前端）与数据版权归原作者；本仓库只实现抓取与规范化

## 源适配：nanoka.cc

| 用途 | 地址 |
|---|---|
| 版本清单 | `https://static.nanoka.cc/manifest.json`（`[game].latest` / `live` / `available`） |
| 页面 | `https://static.nanoka.cc/{game}/{version}/{page}.json`（`{locale}` 取 `zh`） |
| 详情 | 同上，路径按 `detailEndpointPatterns`（`{id}` 占位） |

要点：

- 页面内容是 **dict：记录 id → 记录对象**（少数页为数组），记录字段多语言（`zh`/`en`/`ko`/`ja`）
- 版本来自 manifest 的 `latest`，URL 里需要 `encodeURIComponent`（zzz 版本带 `+` 号）
- **zzz 终局页（`boss` / `shiyu`）的页面记录自带 `live_begin` / `live_end`** —— 绝区零终局期索引由此产出（旧后端没导出这层信息）
- 详情默认不抓；调用方传 `withDetails: true` 才逐条请求（CLI：`--with-details`）
- 页面 hash 与版本都没变才跳过；沿用 manifest 续跑语义
- 与玉璃重叠的页面**保留不裁剪**（消费者自行取舍）：gi 的 tower / rolecombat / leyline 期时间与玉璃重复、可作交叉校验；hsr 四个终局页的 begin / end / live_begin / live_end **全为空串**，期时间只能取玉璃
